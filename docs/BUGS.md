## 实际开场与下一阻塞

2026-11-06，单人无跟随者 `0x70` 行走和 `0x6C` 相对 NPC 位移/动画接入后，以下命令在逻辑模型中从真实 NewSession 执行场景 1 OnEnter **PC 7952 → 8144 (`stop1`)**，返回入口 8145，`completed=true`、`committed=true`：

```sh
go run ./cmd/palverify enter -data "$PAL_DATA" -layout dos -encoding big5 \
  -mgo "$PAL_DATA/mgo.mkf" -scene 1 -out reports/opening.paltrace.json
```

该次调用有 193 个顶层步骤、130 个装备子步骤、76 个 tick、60 个自动工作子步骤、67 次消息引用。初始化装备重建另有 130 条指令及独立 10,000 步预算，不混入调用计数。完成后 NPC 11 为 `(1152,384)`、state 0、auto 4458，领队为 `(1344,288)`。此前精灵加载、受限自动更新和单人队伍行走的开场阻塞已推进，不再把 PC 7976/8059/8073 记为当前阻塞。

`TestLocalOpeningAndPickupSequence` 继续在同一会话调用事件 5/6/7，取得物品 99/201/236 各 1、记录消息 ID 1025/1026/1027、隐藏对应事件，重复调用 5 被拒绝且状态不变。随后事件 1 离场在 **PC 4669 / 0x123d，opcode 0x0050（淡出）** 阻塞；失败调用不提交，先前完成的开场状态及物品保持不变。补齐淡出后仍需解决 `SceneLoadPending` 地图/GOP/事件资源加载。

当前受限等待只接受 operand 1/2 都为零，自动指令子集为 `0/1/2/3/6/9/0x10/0x49/0xFFFF(dos)`；自动触发调用等未知操作仍阻塞。每条等待含其全部自动子工作原子提交，失败不消费输入或更新活动会话。上述结果证明该段逻辑顺序与断言，不证明调查距离/方向、空间触发、原版可执行对照或完整主支线。

初始场景地图/GOP/事件精灵整体加载仍未实现；当前真正 MGO 解压仅接入 `0x65/0x75` 玩家精灵重载。事件 `SpriteFramesAuto` 的资源回填、现场渲染及碰撞需独立验证，不能把导入表中的帧数字段当作已加载完整资源。

## 当前样本检查点与边界

- `paldata`：四张主表、角色、敌人、敌队及商店导入/引用检查；SSS 末条场景作为事件终止边界，M.MSG 的 2 个未索引尾字节保留警告。
- 新游戏初始化：先运行 130 条装备回调，恢复 61 个非零装备效果项及角色 ID 1 的双击状态计数 32760，保留回调后的 `LastEventID=5`；证据独立于后续场景调用。
- `palgame`：完整且输入精确的调用才提交；未知/不完整/剩余输入的调用只保留诊断前缀。旧 `AssumeSceneEntered=true` 检查点回归继续通过；新增 `TestLocalOpeningAndPickupSequence` 先完成真实初始化和 OnEnter，再验证三处拾取与离场失败回滚。
- 新回归不跳过场景 1 OnEnter，但显式事件调用不检查调查距离、方向、碰撞或原版运行结果；后续场景尚未完成，不能关闭 WIN98-002/005/007 的完整流程要求。
- 现有原创战斗和故事扩展是独立预览规则，不等于原版 PAL1 战斗/经验/装备行为。
