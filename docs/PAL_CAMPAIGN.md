# 分段连续流程验证

`palverify campaign` 将多个路线段放在同一个实际 `Session` 中顺序执行。它解决单路线最多 10,000 动作、1 MiB 输入以及单报告 32 MiB 的规模限制，不重置场景、不恢复存档，也不注入世界状态。普通 `journey` 仍要求从新游戏 `enter` 开始。

清单只接受以下两个字段，路径相对于清单所在目录解析，也可使用绝对路径：

```json
{
  "version": 1,
  "segments": [
    "routes/01-opening.json",
    "routes/02-island.json",
    "routes/03-return.json"
  ]
}
```

每段使用 `journey` 的相同路线格式，保留 `version`、`name`、七个 `files_sha256`、可选的 `optional_files_sha256` 及动作。所有段必须固定相同的资源摘要，并采用相同编码与布局。首段第一动作必须为 `enter`；后续段可直接从 `move`、`interact` 等动作开始。后段的 `enter` 仍检查当前会话是否真正需要进入场景，不能把它当成重置命令。

```bash
palverify campaign \
  -data /path/to/local-data \
  -manifest /path/to/campaign.json \
  -out-dir /path/to/new-report-directory \
  -max-steps 100000
```

默认采用路线首段的编码与布局，也可通过 `-encoding big5 -layout dos` 明确选择；与任何一段冲突时会拒绝执行。`-max-steps` 是每个动作的统一工作预算，默认 10,000，最大 100,000。长剧情包含合法嵌套自动脚本时可显式提高预算。默认生成精简成功记录；`-compact=false` 保留完整成功轨迹，失败动作始终保留预算允许的完整诊断。

战斗默认 `-battle-mode auto_attack`。显式使用 `-battle-mode fast_verify` 会把每场独立敌人模板的非零初始 HP 降为 1，仍运行实际数值回合、脚本与奖励。它会改变回合覆盖与生命值条件分支，不能证明原版战斗平衡，也不保证取胜；总索引及每段报告都会保留策略和简化说明。

运行前会读取、校验全部段的格式、来源摘要及布局，才开始执行第一个动作。缺失或错误的后段不会导致前段先运行。输入仅接受普通非符号链接文件，重复路径、硬链接别名以及完全相同的路线文档会被拒绝。上限为 256 段、路线累计输入 64 MiB、累计 250,000 动作；每段仍保留原来的 1 MiB、10,000 动作上限。

输出目录可以已存在，也可以由命令新建一层，其父目录须已存在。路径不接受符号链接目录别名。所有预定输出必须不存在；重复验证请使用新目录。输出只包含 JSON，发布采用原子且不覆盖已有文件的方式，禁止覆盖清单、任一路线、游戏资源或已有报告，包括文件别名。

成功或执行中失败时，目录包含已执行段的 `segment-0001.json` 等报告，以及 `campaign.json` 总索引；标准输出同样是总索引 JSON。预检失败时不创建报告目录，也不执行会话动作。

总索引记录清单 SHA-256、每段路线与报告 SHA-256、实际资源摘要、执行策略、动作数量，以及每段完整 `SessionSnapshot` 的前后 SHA-256。快照包含累计已提交动作数，不能在段间清零。每段 `initial_sha256` 应等于前段 `final_sha256`；完整世界保存在相应段报告的 `final` 中。第二段以后的初始化记录仅描述最初的新游戏引导，并未重新执行。

`action_summary_sha256` 按实际动作顺序累计前后快照摘要、工作量、消息 ID、战斗概要、提交/断言结果与错误，排除段内动作编号和详细轨迹。同一动作流采用不同分段时，可以据此比较执行摘要；它不代替逐条轨迹或游戏本体对照。

某段失败时立即停止，保留已经提交的前序动作、前段报告及当前段可用失败诊断；后续段标记 `not_run`。若失败来自动作后的预期断言，报告仍如实记录该动作已经提交。总索引会标记失败段及最终快照摘要。所有 `full_game_verified` 均为 `false`：清单全部执行完毕只代表该清单覆盖的流程通过，不代表主线与全部支线已经通关。
