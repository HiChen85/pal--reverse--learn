# PAL1 Windows 布局只读导入

`Load(dir, Options{Encoding: "big5"})` 或明确选择 `gbk`。仅打开目录中大小写不敏感、名称无歧义的 `SSS.MKF`、`DATA.MKF`、`M.MSG`、`WORD.DAT` 普通文件。拒绝符号链接。返回每个文件实际名称、字节长度和 SHA-256，便于绑定后续审计证据。不会下载、启动或写回游戏数据。

`Game.Profile` 是调用者请求的 Windows 表结构配置标签，**不是已检测到 Windows98 柔情篇版本**。没有真实数据时，测试只能验证合成结构，不能验证主线、支线或实际游戏行为。GBK/Big5 也是显式配置，不能从所选配置推断资源真实编码。

## 格式依据

公开参考固定为 `sdlpal/sdlpal` 提交 `d4bf69b64d335cd680555af9df90e7ec4f3006a3`，只用于描述格式。实现为独立 Go 解析器，没有复制或翻译上游 C 实现。

- `global.h` 的 `EVENTOBJECT`：16 个 little-endian 16 位字段，共 32 字节。`VanishTime`、`Layer`、`State` 按有符号数解释，同时 `Event.Raw` 保留全部原始 16 位值。
- `global.h` 的 `SCENE`：地图、进入脚本、传送脚本、事件边界四个 WORD，共 8 字节。
- `global.h` 的 Windows `OBJECT`：7 WORD，共 14 字节。对象联合类型需要额外上下文，所以这里只保存原始七字段，不把每一字段都当脚本地址。
- `global.h` 的 `SCRIPTENTRY`：操作码和三个 WORD 操作数，共 8 字节。
- `global.c` 的 `PAL_ReadGlobalGameData` / 默认数据加载：SSS 块 0/1/2/4 分别为事件、场景、对象、脚本；DATA 的 0..14 含各运行时表。本模块仅对 DATA 容器做目录校验和块大小清单，不声称已解码战斗数据。
- `text.c` 的文本加载分支：SSS 块 3 是 M.MSG 的 uint32 little-endian 消息边界，n+1 边界构成 n 条消息。消息和指令按文件直接零基索引保存；游戏事件编号通常从 1 开始，映射 `Events[id-1]`。
- `palcfg.c` 默认词宽为 10；按 10 字节分槽，允许最后一个不完整槽并以零填充解码；保留原始记录的真实长度，并去掉末尾空格/NUL 得到展示值。原始 `1` 后缀不剥离，便于审计与显示层分开解释。

## 验证和覆盖边界

验证容器偏移、事件/场景/对象/指令完整记录宽度、事件/场景脚本引用、场景事件边界，以及位于 M.MSG 内且单调的消息偏移。`0xffff` 指令的消息索引越界会保留指令并记录在 `Game.Warnings`，供后续可达性审计明确阻断。所有资源均设置文件、记录数、消息长度上限。遇到无法映射的编码字节时拒绝读取，不悄悄替换乱码。

允许未索引的 M.MSG 前后字节，并在 `Game.Warnings` 明确记录每端的字节数，防止把仅被索引的消息表误报为完整文件文本覆盖。场景表不强制全表事件边界递增，因为未使用场景可能包含零填充；分场景运行的边界检查由后续审计器负责。

`0xffff` 在 trigger 中可显示对话，在 Windows auto 脚本中也可显示物品描述；单凭 opcode 不给文本贴主线/支线标签。

`RawMessages` / `RawWords` 保留实际文本字节，`Messages` 保留解码后的颜色、速度等控制语法。导入器不执行或移除这些语法，不声称文本枚举等同可达路线。未知 opcode 与对象字段没有被重解释成已验证行为。
